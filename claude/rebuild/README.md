# Clean rebuild: runbook (Step 2.3, D-196, D-217)

A fresh WordPress on **new hosting**, built only from trusted sources. Nothing is copied as files from the compromised Hostinger account (F-033, F-035). This builds a **staging** copy (noindex). The switch to reinforcelab.com is a separate runbook (`claude/migration-checklist.md`, A6) and needs Jamil's go.

| Comes from | What |
|---|---|
| wordpress.org (checksums verified) | WordPress 7.1.3, Yoast SEO, LiteSpeed Cache, Jetpack |
| Jamil's vendor accounts (zips) | Beaver Builder Pro, Beaver Themer, PowerPack, ACF PRO, Yoast SEO Premium, Beaver Builder Theme |
| This git repository | Our site code (`wp/novamira-sandbox/`), loaded by `mu-plugins/reinforce-lab.php`. **No Novamira** (Rule 1) |
| `claude/data/site-export/` | Pages, posts, projects, media records, menus, settings, 3 authors. Data only, scanned (0 risky fields), no passwords or keys |
| reinforcelab.online, file by file | 2,343 images, PDFs and fonts, each matched to its recorded sha1 and file type |

## Files

| File | Does |
|---|---|
| `rebuild.sh` | The whole run, steps 0 to 12, logged to `logs/` |
| `plugins.json` | Which plugins and theme, where each comes from, and what must never be installed |
| `import.php` | Writes the export into the fresh database with the same IDs (front page 33, blog 220, attachments, menus). Refuses to run on a site that is not a fresh install |
| `media.php` | Downloads each media file and keeps it only if sha1 and file type match. Re-runnable |
| `mu-plugins/reinforce-lab.php` | Loads our code from `wp-content/novamira-sandbox/` |
| `novamira-sandbox.htaccess` | Blocks direct requests to our PHP files (only CSS, JS, fonts, images served) |
| `htaccess-410.conf` | Generated by `python3 claude/tools/redirects.py htaccess`: approved 410s for old files under `/wp-content/`, only when the file is missing |

## What Jamil does first (once)

1. **New hosting account** (not the old Hostinger account), PHP 8.2 or newer, MariaDB or MySQL, SSH access with WP-CLI. A staging address, for example `staging.reinforcelab.com` or the host's temporary domain.
2. **An empty database** and its user. Keep the name, user and password private: they go into the server's environment, never into chat or git.
3. **Download the 6 vendor zips** from his accounts (`plugins.json` says where) and upload them to one folder on the server, for example `~/rl-vendor/`.
4. Licence keys are entered by Jamil in wp-admin after the run (they were never exported).

## The run (Claude or Jamil, over SSH on the new server)

```bash
git clone https://github.com/jamilahmed16/reinforce-lab-wp-modernization.git rl && cd rl
git checkout claude/great-wright-cg4kqo      # or main after the merge
python3 claude/tools/export-site.py          # refresh the export first if .online changed (needs Novamira access; can run from Claude's session instead)
export DB_NAME=... DB_USER=... DB_PASSWORD=... DB_HOST=localhost
bash claude/rebuild/rebuild.sh --path ~/public_html --url https://STAGING-ADDRESS --vendor ~/rl-vendor --source https://reinforcelab.online
```

The script stops at the first problem and says why. It refuses to run if the folder already holds a site, if the address is reinforcelab.com, if a vendor zip is missing or has the wrong folder inside, if the export scan is not 0, or if a banned plugin (Novamira, WooCommerce, WP File Manager, WPCode) is present.

## Checks after the run (Step 3, gate)

From the repository (Claude's session):

```bash
python3 claude/tools/redirect-test.py https://STAGING-ADDRESS   # 0 failures required
python3 claude/tools/link-scan.py https://STAGING-ADDRESS       # 0 bad links (3 waiting on unwritten posts, D-216)
```

Then: page parity for the 17 kept pages, accessibility (axe), speed, and a look at Home, a service page, a post and the blog on desktop and phone.

## Tested so far (23 Oct)

Local test in Claude's sandbox on a throwaway WordPress with SQLite (the only copy reachable there; wordpress.org is blocked from the sandbox): the import wrote 387 records with the same IDs, 27 terms, 266 settings and 3 users; a second run refused (site not fresh); 30 media files downloaded and matched; pages served through our code without Novamira; redirect test passed for everything that does not need Yoast or the web server's `.htaccess` (category addresses without `/category/` and author feeds need Yoast, old-file 410s need `.htaccess`). Not testable there: WP-CLI `search-replace` (SQLite), plugin installs. The first full run is on the new hosting.
