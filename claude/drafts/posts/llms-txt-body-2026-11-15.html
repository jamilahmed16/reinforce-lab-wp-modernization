llms.txt is a proposed plain-text file, written in Markdown and placed at the root of a website, that gives language models a short guide to the site and links to its most useful pages. It is not a web standard, and the evidence so far shows that few AI tools read it. Google says Google Search does not use it, a 2026 Ahrefs study found that 97% of llms.txt files received no requests in a month, and an SE Ranking study found no link between having the file and being cited. Adding one is cheap and harmless, but it should come after the basics that do move results.

This guide explains what llms.txt is, who reads it, what the data shows, whether you should add one, and how to write one if you decide to. It includes a sample file, a way to test it and a worked example. We cite only sources we could read at the publisher, and we state the limits of each study.

What is llms.txt?

The llms.txt file was proposed by Jeremy Howard in September 2024. The proposal calls for a Markdown file at /llms.txt on a website, or at a subpath such as /docs/llms.txt, that offers brief background, guidance and links to detailed pages. The idea is to give an AI model or agent a clean, short map of the site, so it does not have to wade through navigation, scripts and ads in ordinary HTML pages.

The proposal also suggests that pages with information agents might need provide a clean Markdown version at the same address with .md added, and that sites use standard link relations to point to those files. The proposal was updated in 2026, so check the current text at llmstxt.org if you build one.

What does an llms.txt file contain?

The proposed format is simple. It has these parts, in order:

  • A heading of level one with the name of the site or project. This is the only required part.
  • A quote block with a short summary of the site, containing the key facts needed to understand the rest of the file.
  • Optional paragraphs or lists with more detail on how to read the files.
  • Optional sections, each with a level-two heading, that hold lists of links. Each list item has a Markdown link and, if you like, a colon and a short note.
  • An optional section named "Optional" for secondary links that an agent can skip when it needs less context.

Here is a short sample for a made-up company:

# Example Co

> Example Co makes scheduling software for medical clinics in the United States. Plans start at a fixed monthly price per location.

Key facts: founded in 2018, based in Austin, Texas. Support is available on weekdays.

## Product

- [Features](https://www.example.com/features/): What the software does and who it is for
- [Pricing](https://www.example.com/pricing/): Plans, prices and what each includes
- [Integrations](https://www.example.com/integrations/): Systems it connects to

## Help

- [Setup guide](https://www.example.com/help/setup/): Step-by-step setup for a new clinic
- [Security](https://www.example.com/security/): How patient data is protected

## Optional

- [Blog](https://www.example.com/blog/): Articles and updates

Who reads llms.txt?

This is the key question, and the answer today is "very few tools." We found three sources.

  • Google says Google Search does not use it. In its guide to generative AI features, Google lists llms.txt files among things you do not need, because Google Search itself does not use them. It adds that creating one is fine for other services that use it, and will neither harm nor help your visibility in Google Search.
  • Almost no one requests it. Ahrefs studied 137,210 domains in its Web Analytics product that received traffic in May 2026. It found that 28% published an llms.txt file, and that 97% of those files received no requests at all that month. Of the requests that did arrive, 96% came from bots. Among named AI tools, GPTBot made the most requests, and Claude Code was second. Ahrefs also found that AI bots never asked for llms.txt files that did not exist, so publishing one does not put you on an AI radar. Limits: Ahrefs customers skew technical, so the 28% adoption is an upper bound, a fetch does not prove a read, and the study did not check whether files followed the specification.
  • No measurable link to citations. SE Ranking analyzed nearly 300,000 domains. It found llms.txt on 10.13% of them, with adoption about the same across low, mid and high traffic sites. It reported no correlation between having the file and how often a domain was cited by AI tools, and its model got slightly more accurate when it removed the llms.txt factor. Limits: it is an observational study of one dataset, it has no crawler logs, and the authors call the results context-dependent. It bounds the size of any effect and does not prove that no effect exists for any site.

The two studies used different methods and data, and they point the same way. Neither one shows that major AI search tools use the file to decide what to cite.

Does llms.txt help you get cited by AI tools?

We found no evidence that it does. OpenAI's documentation tells site owners to allow OAI-SearchBot and to allow requests from its published IP addresses. It does not mention llms.txt as a factor. ChatGPT search, Google's AI features and Perplexity retrieve pages through their own search systems, and a separate file that lists your best pages does not change which pages those systems retrieve. That is our reading, and the studies fit it, but no one outside the AI companies can say for certain.

There is one group where the file may have more use: tools that read documentation. Ahrefs found that Claude Code was the second most frequent named AI fetcher of llms.txt files, ahead of the AI search bots. That suggests developer tools and coding agents may look for the file when working with documentation. This is an inference from request counts, so treat it as a lead to test on a documentation site, not as proof.

How is llms.txt different from robots.txt and a sitemap?

The three files do different jobs, and only two of them are well established.

FileJobWho reads it
robots.txtTells crawlers which parts of a site they may fetchSearch and AI crawlers that honor it, such as Googlebot, OAI-SearchBot and ClaudeBot
XML sitemapLists the URLs you want search engines to findSearch engines such as Google and Bing
llms.txtOffers a short guide and curated links for language modelsNo major AI platform has committed to it. A few bots and tools fetch it.

If a page is blocked in robots.txt, listing it in llms.txt does not open it. If a page is missing from your sitemap, listing it in llms.txt does not make a search engine index it. So the file cannot fix access or indexing problems. Those need their own checks.

What do the studies prove, and what do they not?

It helps to read the two studies with care, since each answers a different question.

  • Ahrefs measured requests. It asked who fetches llms.txt files. The answer was almost no one in the month it studied. It could not say whether a fetch changed an answer, and it noted that its figures are ceilings on real use.
  • SE Ranking measured an outcome. It asked whether domains with the file were cited more. It found no link. It could not look at crawler logs, so it could not say whether retrieval bots ever requested the files. A fair reading is that any effect is too small to see in that data.
  • Neither covers the future. AI platforms may change what they read. The proposal itself was updated in 2026. If a major platform announces support, the advice here should change, and we would update this guide.

The honest summary is that the file has no proven benefit today and a small, easy cost.

What about Markdown versions of your pages?

The proposal goes further than a single file. It suggests that pages with information agents might need offer a clean Markdown copy, at the same address with .md added, and that sites point to those copies with standard link relations or HTTP headers. This helps most when a page is hard to read, for example when it is full of scripts, tabs or widgets. For ordinary articles that already render clean HTML, the benefit is smaller. If you try it, serve the same content as the page, since showing a model different facts from what people see risks trust problems. Test on a small set of pages first, and check logs to see whether anything fetches them.

Should you add an llms.txt file?

Type of siteOur viewWhy
Developer documentation or API siteWorth tryingCoding tools and agents may read it, and docs are already structured
Software company marketing siteOptionalLow cost, no proven effect. Do access, answers and facts first.
Local or service businessLow priorityAI answers rely more on listings, reviews and clear pages
Online storeLow priorityProduct data, feeds and reviews matter more
Publisher or blogOptionalNo evidence of a citation effect

If you add one, the risks are small: a few hours of work, and the file can go out of date. A stale file that points to removed pages or old prices adds wrong facts to a place that tools may read. So add it only if someone will keep it current.

How do you create an llms.txt file?

  1. Pick your most useful pages. Choose 10 to 30 pages that explain who you are, what you offer, prices, help and key policies.
  2. Write the summary. One or two plain sentences with the key facts. Use the same name and description you use everywhere else.
  3. List the links. Group them under clear headings, with a short note for each that says what the page contains.
  4. Keep it short and true. Do not add claims you would not put on your site. Do not stuff it with keywords.
  5. Publish it at the root. Make it available at yoursite.com/llms.txt with a normal 200 response. Open it in a browser to check that it shows as plain text.
  6. Keep it current. Review it whenever you change prices, services or key pages.

Many "llms.txt generator" tools can draft a file from your sitemap. Because the file is short, writing it by hand takes little time, and it lets you choose which pages matter. If you use a generator, read the output and remove pages you do not want promoted, such as thin or outdated ones.

The file does not control access. It is not a replacement for robots.txt. To allow or block AI crawlers, use robots.txt and your firewall settings. Our robots.txt guide explains the file.

How do you test whether llms.txt does anything on your site?

Treat it as an experiment with a clear test.

  1. Check your logs. After you publish, look at your server or CDN logs for requests to /llms.txt. Note the user agents. If nothing asks for it in a month, you have your answer for now.
  2. Run a prompt baseline first. Before you publish, run 10 to 15 buyer questions three times in ChatGPT, Gemini and Perplexity, and record whether you are named and cited. Repeat after 60 days. SparkToro found less than a 1 in 100 chance that the same prompt returns the same list of brands twice, so a change must be large and repeated to mean anything.
  3. Change one thing at a time. If you also rewrite pages in the same month, you cannot tell which change did what.

What should you do before llms.txt?

These steps have better support:

  1. Let search crawlers in. OpenAI says sites that opt out of OAI-SearchBot will not be shown in ChatGPT search answers.
  2. Make pages readable in HTML. In December 2024, Vercel found that none of the major AI crawlers it tested rendered JavaScript.
  3. Answer questions first, with sources. A Princeton-led test of nine content changes found that adding citations, quotations and statistics lifted visibility by up to 40%.
  4. Keep your facts consistent across your site and your profiles.
  5. Earn honest mentions on the sites that AI answers cite.

Worked example: a software company with a docs site

This is an illustration, not a client result. Imagine a company with a marketing site and a separate documentation site for its API. Its docs site has 300 pages, and developers often ask coding assistants how to use it.

The team first checks that crawlers can reach the docs, and that pages render as HTML. It then writes an llms.txt file for /docs/ with a two-sentence summary and 25 links in four groups: quick start, authentication, API reference and troubleshooting. It adds Markdown versions of the 25 pages. For the marketing site, it decides not to add a file yet, because it has no evidence that the file would help there.

After 30 days the team reads its logs for requests to the docs file and notes which user agents asked. It also asks three coding assistants the same 10 setup questions before and after, and records whether the answers use the right steps. It keeps the sheet whatever the result. The file stays only if the logs and tests show that something uses it.

What are the common mistakes?

  • Expecting a ranking or citation boost. No study we found shows one.
  • Treating it as robots.txt. It does not allow or block crawlers.
  • Listing everything. A long file defeats the purpose of a short guide.
  • Letting it go stale. Old prices and removed pages add wrong facts.
  • Publishing a generator's output without a check. Remove thin, old or private pages.
  • Doing it before the basics. Access, readable pages and clear answers come first.

Final thoughts

llms.txt is a small, optional idea with little proof behind it so far. Google says it does not use the file, and two large studies found it either unread or unrelated to citations. If you run a documentation site, try it and test it. For most other sites, fix access, readable pages, clear answers and honest mentions first, and revisit llms.txt if the evidence changes.
