A robots.txt file is a small text file that tells search engines which parts of your website they may crawl. It sits at the root of your site, for example https://example.com/robots.txt. Every well-behaved crawler reads it before it looks at anything else.

This guide explains what the file does, what it cannot do, how to write one, and how to check it. Every rule here comes from Google's own documentation, which is linked at the end.

What is a robots.txt file?

A robots.txt file is a plain text file with rules for web crawlers. A crawler is the program a search engine uses to read web pages. Search engine crawlers are also called bots or spiders. Googlebot is Google's crawler. Bingbot is Bing's.

Each rule says which crawler it is for and which paths that crawler may or may not open. Rules are also called directives. Google says the file is used mainly to manage crawler traffic, so your server is not overloaded with requests.

The rules follow a standard called the Robots Exclusion Protocol. If a site has no robots.txt file, crawlers assume they may crawl everything.

Why is robots.txt important for SEO?

Search engines do not have unlimited time for your site. SEO people call that time your crawl budget. Robots.txt helps crawlers spend it on the pages that matter.

  • It keeps crawlers out of pages with no search value. Think of admin screens, cart pages and internal search results. The same goes for pages that are near copies of each other (duplicate content), such as filtered product lists.
  • It protects your server. On a large site, crawlers can make many requests. Rules reduce that load.
  • It can keep media files out of Google. Google says you can use it to stop images, video and audio files from showing in search results.
  • It points crawlers to your sitemap. One line tells them where the list of your important pages is.

A mistake here can also do real harm. One wrong line can block your entire site from being crawled. That is why this file deserves care.

What can robots.txt not do?

This is the part most guides get wrong, so read it twice.

Robots.txt does not keep a page out of Google. It stops crawling. It does not stop indexing. Google says a blocked page can still appear in search results if other pages link to it. The result will show the address with no description.

To keep a page out of search results, Google tells you to use one of these instead:

  • a noindex tag or header on the page
  • a password on the page
  • removing the page

Do not combine a noindex tag with a block in robots.txt. If the crawler cannot open the page, it never sees the noindex tag.

Robots.txt is not security. The file is public. Anyone can read it. Google also notes that some crawlers do not obey it. Private files need a password, not a line in a text file.

What does a robots.txt file look like?

Here is a simple file with two groups of rules and a sitemap line.

User-agent: Googlebot
Disallow: /nogooglebot/

User-agent: *
Allow: /

Sitemap: https://www.example.com/sitemap.xml

In plain words: Googlebot may not crawl any address that starts with /nogooglebot/. Every other crawler may crawl the whole site. The sitemap is at the address shown.

Google supports four fields in this file:

FieldWhat it doesExample
User-agentNames the crawler the rules are for. A star means all crawlers.User-agent: *
DisallowA path the crawler must not open.Disallow: /cart/
AllowA path the crawler may open, even inside a blocked folder.Allow: /cart/help/
SitemapThe full address of your sitemap.Sitemap: https://example.com/sitemap.xml

Google does not support crawl-delay. Lines it does not understand are ignored.

How do you create a robots.txt file?

Google describes four steps: create the file, add rules, upload it, and test it.

1. Create a file named robots.txt

Use a plain text editor such as Notepad or TextEdit. Do not use a word processor. Word processors can add hidden characters and curly quotes that break the rules.

Save the file as robots.txt in UTF-8 format. The name must be exactly that, in lower case. A site can have only one.

2. Choose the user agent

Every group of rules starts with a User-agent line. It says who the rules are for.

  • One crawler: User-agent: Googlebot
  • Several crawlers: put each name on its own line above the same rules.
  • All crawlers: User-agent: *

A crawler follows only one group: the one that names it most exactly. If there is a group for Googlebot and a group for *, Googlebot follows its own group and ignores the other. The order of the groups in the file does not matter.

3. Add your rules

Under the user agent, add one rule per line. Each path starts with a slash. A folder ends with a slash too.

User-agent: *
Disallow: /wp-admin/
Allow: /wp-admin/admin-ajax.php
Disallow: /?s=

Three things to remember:

  • Paths are case-sensitive. /File.pdf and /file.pdf are different.
  • A star is a wildcard. It stands for any text in a path.
  • A line that starts with # is a comment. Use comments to say why a rule exists.

4. Upload the file to the root of your site

The file must sit in the root directory, the top level of your site, such as https://www.example.com/robots.txt. Crawlers do not look for it in a folder.

The file only covers the exact site it is on. Rules on https://example.com do not apply to https://shop.example.com. Each subdomain needs its own file.

On some website builders, such as Wix or Blogger, you may not be able to edit the file yourself. Google says to use the platform's own search settings in that case. On WordPress, SEO plugins such as Yoast SEO let you edit it from the dashboard.

5. Test it and keep it up to date

First, open the file in a private browser window. If you can see your rules, crawlers can too.

Then open the robots.txt report in Google Search Console. Google lists it as the way to find and fix problems in a file that is already live.

Check the file again after every site change, launch or migration. Google usually keeps a copy for up to 24 hours, so a change may take a day to be picked up.

Robots.txt examples you can copy

These are the rules most sites need. Change the paths to match your own site.

Allow everything

User-agent: *
Disallow:

An empty Disallow line blocks nothing. This has the same effect as having no file at all.

Block one folder

User-agent: *
Disallow: /checkout/

Every address that starts with /checkout/ is off limits to all crawlers.

Block a folder but allow one file in it

User-agent: *
Disallow: /downloads/
Allow: /downloads/price-list.pdf

The more exact rule wins, so the price list can still be crawled.

Block one type of file

User-agent: *
Disallow: /*.xls$

The star stands for any text. The dollar sign marks the end of the address. Together they match every address that ends in .xls.

Block one crawler only

User-agent: GPTBot
Disallow: /

User-agent: *
Allow: /

Here one named crawler is kept out and all others are welcome.

Add your sitemap

Sitemap: https://www.example.com/sitemap.xml

Use the full address. You can list more than one sitemap, each on its own line.

What are the most common robots.txt mistakes?

  • Blocking the entire site. The directive Disallow: / under User-agent: * stops all crawling. This is often left over from a test site.
  • Using it to hide pages. Blocked pages can still be indexed. Use noindex instead.
  • Blocking files a page needs. Google warns against blocking style and script files if the page is hard to understand without them.
  • Putting the file in a folder. It only works at the root.
  • Forgetting subdomains. Each one needs its own file.
  • Letting the file break. If your server returns an error for robots.txt, Google stops crawling the site for the first 12 hours. It then uses the last good copy for up to 30 days.
  • Making it too big. Google reads only the first 500 kibibytes.

Robots.txt best practices

  • Keep the file short. Fewer robots.txt rules mean fewer mistakes.
  • Block sections, not single pages. Use one rule for a folder where you can.
  • Add the sitemap directive. It helps crawlers find your important pages.
  • Write a comment above each rule. Say why it is there, so the next person does not have to guess.
  • Check Search Console. A page marked as blocked by robots.txt there should be one you meant to block.
  • Review the file after every launch or migration. Test sites often carry a rule that blocks everything.

Robots.txt and AI crawlers

AI tools read the web too, and each one has its own crawler name. You can allow or block them in robots.txt like any other crawler.

Crawler nameWho runs itWhat it is for
OAI-SearchBotOpenAIShowing sites in ChatGPT search answers
GPTBotOpenAICollecting content that may be used to train its models
Google-ExtendedGoogleControls use of your content for Gemini training and grounding

Two facts matter here. OpenAI says sites that block OAI-SearchBot will not be shown in ChatGPT search answers. Google says Google-Extended does not affect your place in Google Search.

So decide on purpose. If you want AI answers to name and cite your business, do not block the search crawlers. At Reinforce Lab we allow them on our own site, and we block only the admin area and internal search pages.

Robots.txt or a meta robots tag: which one?

They do different jobs. Use the one that fits the goal.

Your goalUse this
Stop crawlers wasting time on a sectionRobots.txt
Keep one page out of search resultsA noindex meta tag
Keep an image or video file out of search resultsRobots.txt
Keep a PDF out of search resultsA noindex header
Keep something privateA password

Robots.txt works on whole sections of a site. A meta robots tag works on one page at a time.

Wrapping up

Robots.txt is short, but it controls how every crawler meets your site. Keep it simple. Block only what has no search value. Never use it to hide pages. Test it after every change.

If your pages are not being crawled or indexed and you are not sure why, the robots.txt file is the first place to look.
